## Additional acceptance scenarios executed in this audit

The existing parameterized tests were searched before adding coverage. They covered five-fighter recovery-special exhaustion/landing, throws, passive resources and many reset cases, but did not directly execute ledge return, double-jump exhaustion, aerial-dodge exhaustion, DI magnitude/angle, KO contributor history or the full Party warning interval.

Added 31 checks to `tools/validation/combat_scenarios.gd`, using `MatchWorld.step` and ordinary `ScriptedInputProvider` edges. Test fixtures set initial positions/resources; actual attacks, jumps, dodges, collisions, damage and state transitions use the game. No runtime or source-art code was changed by this audit. Both left/right ledges return to the main deck; an exhausted double jump cannot repeat; aerial dodge has vulnerable recovery, rejects a second use and refreshes only after landing; vertical DI changes a real hit's angle by less than seven degrees without changing speed; two actual attackers produce last-hit credit and unique stock contributors, then reset/expiry work; the actual Party marker/audio event precedes actual damage by 72 ticks.

Executed command from the repository root:

```powershell
& 'D:\Game Engines\Godot\Godot_v4.7.2-stable_win64_console.exe' --headless --path 'Game File' --script '../tools/validation/combat_scenarios.gd' --log-file 'C:\Users\dayw9\Desktop\Codex\Games\Godot\Fighting Game\evidence\completion_audit_combat.log'
```

Final result: **95 checks, zero failures, zero console errors/warnings**. Evidence: `evidence/combat_scenarios.json` and `evidence/completion_audit_combat.log`. The initial new aerial-dodge fixture used Godot's negative-Y `Vector2.UP` despite the input contract being positive-Y-up, causing early landing; correcting that fixture made all checks pass. That was a test error, not a runtime fix.
